# Ikris Pharma Network — Logistics Control Tower

Live tracking of NPP (Named Patient Program) and Recordati / rare-disease medicine shipments, from **Inquiry** to **POD received**, with role-based access.

**Live:** https://ikris-logistics-control-tower.vercel.app · Database: Supabase project `ikris-logistics-control-tower` (ap-south-1)

**Stack:** React 18 + TypeScript + Vite · Tailwind CSS · Recharts · React Hook Form + Zod · React Toastify · Supabase (Postgres, Auth, RLS, Realtime, Storage) · Vercel.

## Roles

| Role | Sees | Can do |
|---|---|---|
| `admin` | NPP **and** Recordati | Everything, plus archive shipments, manage users/roles, audit log, thresholds |
| `npp` | NPP only | Create/update NPP shipments, notes, payments, holds, documents, NPP stock |
| `rare_disease` (Recordati team) | Recordati / rare disease only | Same, for Recordati records |

Access is enforced **in the database** (Row Level Security + `SECURITY DEFINER` functions that read `auth.uid()`), not by hiding UI. See [`docs/SECURITY.md`](docs/SECURITY.md).

## The 11 stages

`Inquiry → Payment received → Import permit → CDEC form signed → CDEC approved → Order placed → Shipped → In customs → Cleared → Delivered → POD received`

* Stored as a Postgres enum (`public.shipment_stage`) — no other value can be saved.
* Stage changes only through `update_shipment_stage()`, which updates the shipment and writes the history row in one transaction. Moving backwards requires a correction reason.
* **On hold** is a flag (`is_on_hold` + `hold_reason`), not a stage.
* **Stuck** = no update for 5+ days, or more than 7 days in customs (configurable in Settings; on-hold excluded).
* Shipment IDs: `NPM-0001…` (NPP) and `RDM-0001…` (Recordati), generated by Postgres sequences.

## Local setup

```bash
cp .env.example .env.local     # fill in the project URL + publishable key
npm install
npm run dev
npm test                       # unit tests (stage rules, error masking)
npm run build                  # typecheck + production build
```

## Database setup (new environment)

Apply the files in `supabase/migrations/` in order (Supabase CLI `supabase db push`, or the SQL editor). Then:

1. **Authentication → Providers → Email:** turn **off** "Allow new users to sign up". Accounts are created by an admin.
2. Create users (Authentication → Users → Invite) and insert a row in `public.profiles` with their role.
3. Set **Site URL** / redirect URLs to the Vercel domain so password-reset links work.

## Deployment (Vercel)

* Framework: Vite · Build: `npm run build` · Output: `dist` (see `vercel.json`, which also sets CSP and security headers and SPA rewrites).
* Environment variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (publishable key only). **Never** put the service-role key in a `VITE_` variable.

## Legacy data migration

Imported on 21 Oct 2026 from:

* **NPP UPDATE** sheet → tabs `NPM` (149 shipments) and `Recordati` (10 → Recordati department)
* **Recordati All India Data** sheet → tab `TOT Sheet` (247)

Rules (see `scripts/migrate_sheets.py`): latest dated column wins over "Overall Status"; any column saying *delivered* marks the row Delivered; unrecognised or contradictory text sets `needs_review` with an explanation (70 rows); 2025 TOT orders with no final status were archived (23). Daily status columns became timeline entries. Phone numbers and Aadhaar columns were **not** imported. The original sheets stay as a read-only archive.

## Google Sheets mirror

Supabase is the source of truth. A Claude scheduled task (08:41 and 17:41 IST daily) copies shipments into the tab **CT Export (Supabase)** of each department's own sheet (NPP rows → NPP UPDATE sheet, Recordati rows → Recordati sheet). It is one-way: edits made in the sheet are not read back.
